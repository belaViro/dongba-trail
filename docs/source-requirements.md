1. 文档目的与项目背景

本文件用于将“东巴文字视觉识别 + 丽江文旅商户引流”构想整理为可直接进入研发评审、任务拆分和迭代排期的研发文档。项目不以单一OCR或图像分类Demo为最终交付，而以“游客识别—文化解释—地点/商品/商户推荐—地图导航—领券到店—集章分享—数据回流”为完整产品闭环。

现有资料包含大量东巴象形文字的“编号—中文释义—图形写法”对应关系，覆盖自然、人、服饰、饮食、器物、生产生活、建筑、民俗等多个类别，可作为首期结构化字典与训练数据整理的重要来源。研发阶段必须将资料转换为可训练、可检索、可运营的数据资产，而不是直接把PDF作为模型输入。

1.1 产品定位

| 项 | 定义 |
| --- | --- |
| 暂定产品名 | 东巴寻迹 · 丽江 |
| 一句话定位 | 拍一拍东巴文字，读懂它的含义，找到丽江与它相关的人、店、物和故事。 |
| 核心用户 | 丽江游客、本地商户、文旅运营方、文化内容运营人员 |
| 核心价值 | 游客获得文化探索体验；商户获得自然流量；运营方获得可量化的文化传播与消费转化数据 |

2.2 V1.0 暂不做

（1）不做“全句东巴文翻译”；首期以单字/单词条识别为主，复杂组合图形只返回候选及人工解释。

（2）不做开放式UGC商户自行发布文化解释；文化内容必须走运营审核。

（3）不做复杂支付结算与商户佣金分账；V1.0优惠券以领取、核销、引流验证为主。

（4）不将生成式大模型作为唯一识别引擎；多模态模型仅用于低置信度解释或辅助候选，不代替可控视觉模型。

（5）不承诺全部东巴字一次性达到商用准确率；先选取高频、易采集、可与文旅场景关联的核心字集完成MVP。

3.1 典型用户旅程

游客在古城招牌、文创、墙面或门店看到东巴文字，打开小程序。

点击“拍照识东巴”，拍照或从相册选择图片。

系统检测图像质量；若模糊、过暗、目标过小则提示重拍。

AI识别后返回Top-1结果和Top-5候选；高置信度直接展示结果，低置信度要求用户确认。

结果页展示中文释义、不同写法、简短文化解释、音频/图文内容。

系统根据该字的“文化主题—商品—商户—POI”关联关系，展示附近可探索地点。

用户导航到店或领取优惠券；到店后扫码/店员核销。

用户获得“东巴印记”，继续完成城市寻迹任务。

完成阶段任务后生成分享海报；识别图片和用户纠错结果进入样本回流池。

4.3 数据集制作流程

PDF/原始资料
  → 页图像提取
  → 词条区域切分
  → 编号/中文释义/图形关联
  → 同字多写法归并
  → 人工复核
  → 基础数据增强
  → 构建 train/val/test
  → V1 模型训练
  → 采集游客/门店真实照片
  → 线上难例回流
  → V2/V3 持续训练

建议首期先建立“核心高频字集”，优先纳入与丽江旅游和消费场景关联度高的类别，如自然、饮食、服饰、建筑、生活器物、民俗活动等；之后再扩充到全量字库。

5. AI识别技术方案

5.1 推荐模型架构

| 层级 | 建议方案 | 作用 |
| --- | --- | --- |
| 图像质量检测 | 轻量规则 + OpenCV指标 | 判断模糊、过暗、过曝、目标过小 |
| 目标检测 | YOLO11/YOLOv8 | 检测图片中的东巴文字/图形区域 |
| 分类 | ConvNeXt / EfficientNet / ResNet / ViT | 固定核心字集Top-1/Top-5识别 |
| 向量检索 | DINOv2 / SigLIP / CLIP类图像Embedding | 处理同字异形、未见变体、近似检索 |
| 低置信度兜底 | 多模态模型 + 规则 | 辅助解释候选，不直接覆盖主模型结果 |

V1推荐采用“检测 + 分类”作为主路径，“Embedding相似检索”作为补充；避免直接用通用OCR解决象形文字识别。

5.2 推理逻辑

if image_quality < threshold:
    return NEED_RETAKE

boxes = detector(image)
if not boxes:
    return NO_TARGET

for box in boxes:
    crop = crop_image(image, box)
    cls_top5 = classifier(crop)
    emb_top5 = vector_search(crop)

    result = fusion(cls_top5, emb_top5)

    if result.top1_score >= HIGH_CONF:
        status = CONFIRMED
    elif result.top1_score >= LOW_CONF:
        status = NEED_USER_CONFIRM
    else:
        status = UNKNOWN

5.4 模型指标建议

| 指标 | MVP建议值 | 说明 |
| --- | --- | --- |
| 核心字集 Top-1 | ≥90% | 在受控测试集上的首期目标 |
| 核心字集 Top-5 | ≥97% | 用于用户确认和低置信度兜底 |
| 目标检测 Recall | ≥95% | 不漏掉主要东巴文字区域 |
| 单图推理P95 | ≤1.5秒 | 服务端推理，不含弱网传输 |
| 低置信度拒识 | 可配置 | 宁可提示确认，不强行给错误答案 |
| 线上纠错闭环 | 100%可追踪 | 每次纠错保留原结果和确认结果 |

6.1 识别结果页内容层级

1.识别结果：东巴字图形 + 中文名称 + 置信度。

2.同字异形：展示资料中已确认的多种写法。

3.一句话解释：20—50字，适合游客快速理解。

4.文化故事：80—300字，可配音频/图片。

5.在丽江遇见它：关联商户、POI、商品、活动。

6.行动按钮：去看看 / 导航 / 领券 / 收藏 / 加入寻迹。

7.纠错入口：‘识别不对？’ → 用户选择Top-5或提交人工复核。

7. 商户导流与推荐模型

商业推荐不能简单等同“附近商家”。推荐应以东巴字/文化主题为主语，通过文化标签与商户经营标签建立关联。

东巴字/词条
  ↓
文化主题
  ↓
商业标签
  ↓
商户 / 商品 / POI / 活动
  ↓
地理距离 + 营业状态 + 活动有效期 + 运营权重
  ↓
推荐排序

| 关系表 | 关键字段 |
| --- | --- |
| character_merchant_rel | character_id, merchant_id, relevance_score, source, status |
| character_product_rel | character_id, product_id, relevance_score |
| character_poi_rel | character_id, poi_id, relation_type |
| merchant_tag | merchant_id, tag_id |
| coupon | merchant_id, title, rule, start_at, end_at, stock, status |

7.1 V1推荐排序

score =
  0.35 * cultural_relevance
+ 0.25 * distance_score
+ 0.15 * merchant_quality
+ 0.10 * coupon_activity
+ 0.10 * user_behavior_match
+ 0.05 * operation_weight

首期可采用规则评分，不需要一开始就上复杂推荐模型。所有权重必须配置化，运营后台可调整。

8. “东巴寻迹”任务系统

寻迹系统是留存、到店和分享的核心游戏化机制。商户不只是广告位，而成为文化任务点。

| 实体 | 字段示例 |
| --- | --- |
| quest | 名称、介绍、城市区域、开始/结束时间、奖励 |
| quest_node | 东巴字、商户/POI、顺序、完成条件 |
| user_quest | 用户、进度、状态、开始时间、完成时间 |
| user_stamp | 用户、东巴字、来源、获得时间 |
| reward | 优惠券/电子证书/文创兑换权益 |

8.1 任务完成条件

（1）识别指定东巴字成功。

（2）扫描指定门店二维码。

（3）到达指定POI地理围栏。

（4）核销指定商户优惠券。

（5）运营人工确认（特殊活动）。

9. 分享传播功能：我的东巴印记

V1可实现轻量版‘我的东巴印记’：用户选择1—3个已经识别或收藏的东巴字，由模板生成分享海报。生成式文案只能作为辅助，必须有敏感词过滤和固定模板兜底。

| 功能 | V1方案 |
| --- | --- |
| 输入 | 用户已收藏/已识别的东巴字，不开放任意姓名自动翻译 |
| 输出 | 东巴字图形、中文含义、短句、丽江背景、分享小程序码 |
| 目的 | 朋友圈/社交平台传播与回流 |
| 风险控制 | 不宣称为权威‘姓名翻译’，避免文化误读 |

17. 测试与验收要求

17.1 AI验收

（1）固定测试集不可与训练集重复，按数据集版本冻结。

（2）至少分别统计字典标准图、数据增强图、真实手机实拍三类准确率。

（3）输出Top-1、Top-5、混淆矩阵、低置信度拒识率、检测Recall。

（4）对相似图形必须建立专项混淆测试集。

（5）模型上线必须记录model_version，支持按版本回溯识别日志。

17.2 功能验收

| 场景 | 验收点 |
| --- | --- |
| 拍照识别 | 相机/相册可用；质量差有提示；识别结果可追踪 |
| 低置信度 | 展示Top-5并允许用户确认；确认进入反馈表 |
| 商户推荐 | 只展示已审核、营业有效的商户/活动 |
| 地图导航 | 坐标准确，可唤起地图路线 |
| 优惠券 | 库存、领取、过期、重复核销规则正确 |
| 寻迹任务 | 任务进度不可重复刷；奖励按规则发放 |
| 后台审核 | 内容、商户、标签状态变更可审计 |
| 数据回流 | 用户纠错可在样本后台查询并进入复核流程 |

21. 关键风险与研发决策

| 风险 | 处理原则 |
| --- | --- |
| 原资料不是标准训练集 | 必须人工结构化、切分、归并和复核，禁止直接把PDF当成训练集完成品 |
| 同字异形明显 | 数据模型必须支持character_variant；评测按‘同一语义类’处理 |
| 真实场景与字典图差异大 | 尽早采集招牌、木牌、墙面、商品等真实照片，建立domain shift专项集 |
| 通用OCR不适配 | 主方案采用目标检测+图像分类/相似检索 |
| 文化解释可能误读 | 文化内容与AI识别分离，解释内容由运营/专家审核 |
| 商户推荐过度广告化 | 推荐必须先文化相关，再考虑距离与运营权重 |
| 冷启动商户不足 | 首期围绕少量示范线路与示范商户，不做全城覆盖 |
| 识别错误伤害体验 | 提供Top-5、低置信度拒识和纠错，不强行输出单一答案 |

22. MVP上线判定条件

（1）核心字集数据全部具备唯一ID、中文释义、至少1个已审核图形样本。

（2）AI测试集Top-1/Top-5达到项目评审约定阈值，且真实实拍集有单独报告。

（3）从拍照识别到字词详情、附近商户、导航、领券至少一条链路完整可用。

（4）至少配置一条完整‘东巴寻迹’示范路线。

（5）识别日志、用户纠错、模型版本、商户转化均可在后台追踪。

（6）发生模型故障、商户下架、优惠券过期时均有可接受的降级逻辑。

附录A：本说明书所依据的资料特征

现有东巴资料为图文型字典/词条集合，包含大量编号、中文释义及对应象形图形。同一含义往往存在多种图形写法，研发时应将其视为同一语义类别下的多个variant。资料中还包含茶、米、酥油、雪茶、麦芽糖、服饰、村庄、房屋、生产生活器具等大量可与丽江文旅场景建立关联的词条，因此适合同时构建“识别字典”和“文化—商业标签库”。
