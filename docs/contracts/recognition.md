# 识别接口边界（第1轮）

生成的HTTP契约：`openapi.json`。代码是契约源，使用 `python scripts/export_openapi.py` 更新。

## HTTP

运行时管理员配置见 `runtime-system-config.md`；环境提供方参数是默认值，数据库更新后下一请求使用新提供方与超时，不必重启。Web 地图 Key 不再写入构建产物配置。

D-042的独立MySQL审核记忆、公开命中字段、候选辅助和故障回退见 [RAG约定](rag.md)。仍须用户确认；RAG不能替代未配置或失败的供应商。

- `GET /health`：进程存活，不证明供应商或数据库可用。
- `GET /ready`：检查提供方配置和发布字典；缺任一项返回503。不代替供应商连通性及效果验证。
- `GET /api/v1/characters/{id}`：返回已发布词条，其他情况404。
- `POST /api/v1/recognize`：multipart字段 `image`、`scene=camera|album`。
- 返回与响应头共享的 `request_id`；每次请求由服务端生成。
- 当前每次请求只处理主目标；不承诺多框检测能力，待供应商验证。

## 状态与错误

- `NEED_USER_CONFIRM`：至少一个候选匹配了已发布词条，需要用户确认。
- `UNKNOWN`：没有候选能够匹配已发布词条。
- `CONFIRMED`：当前不输出；校准规则或用户确认流程实现后再开放。
- 400：图像无效；413：超过文件或像素限制；415：不支持的格式；422：字段验证失败。
- 503：依赖未配置/字典不可用/提供方暂不可用；504：提供方超时；502：输出不符合约定。
- 错误体：`request_id`、`code`、`message`，不包含提供方异常文本或密钥。

## 适配器内部协议

`RecognitionProvider.recognize(image, media_type, characters)` 为异步接口，返回 `ProviderResult`。
候选必须包含标准 `character_id`。供应商仅返回名称时，适配器需要按已审核字典做无歧义映射；禁止自动创建词条。
候选数量最多5个；提供方可选返回 `score`（0至1），业务不将其作为准确率。
输出记录 `provider`、`model_version`。未匹配ID被丢弃，同一ID去重，文化内容从内部字典读取。

已实现可替换供应商、Ark适配器及D-086本地DB1404 CPU适配器；未配置环境仍明确不可用。
`db1404-local`只加载Git外受信任的`inference.pt`，启动/就绪前按配置的SHA-256验证，
使用与训练一致的64×64灰度白底等比填充预处理，只在当前已发布字典ID中排序并最多返回5项。
模型分数未经校准，不代表正确概率，不用于自动确认；模型不具备可靠未知字/非东巴字拒识，
客户端必须保留“都不是”。模型缺失、摘要不符、依赖缺失或加载失败时明确不可用，不静默调用Ark。
Ark作为运营人员手动选择的回滚提供方；两个提供方不自动双调用或混排。

D-088：本地就绪检查在摘要验证后加载CPU运行时（成功缓存复用）；依赖缺失/损坏、模型无法加载
均不可用。管理状态、成功与失败识别记录统一使用实际本地版本，不使用保留的Ark模型ID；
本地运行不依赖备用Ark密钥解密。后台查询不调用外部模型，详见 `runtime-system-config.md`。

Ark参考输入先由本地粗筛取
top-200，再按20字一组拼为10张带标准ID的对照图，最后追加1张待识别图；不减少候选，
避免把200张小图分别计为视觉输入。若上游返回`usage`，服务端仅记录模型、参考数、图片数及
prompt/completion/total token数，不记录图片、密钥或提供方原始响应。自动化测试通过依赖注入
使用固定替身，仅验证编排规则，不证明真实模型效果。

D-077新增可选的`DONGBA_GLYPH_PROTOTYPE_DIRECTORY`：当目录中的部署包完整有效时，
本地粗筛按每类8个DB1404代表写法的最小距离排序，并把该类与查询最接近的原型图放入上述
对照图；仍只输出200个唯一已发布ID和10张对照图。部署包缺失、索引/图片损坏、校验和不符
或不足以覆盖目标候选数时，整次请求回退到D-071单主图粗筛，不混用残缺原型。部署包不保存
用户查询图片，运行时日志也不记录图片内容、凭据或查询摘要。
