# 八轮实施与当前交付

八轮是范围组织方式，实施中允许按接口约定并行推进。每项工作仍按“恢复状态→对照需求→实现→验证→记录证据”完成，不以一轮结束自动停止。

当前执行用户修订后的标准：模型适配占位由用户后补（D-013），数据库使用MySQL（D-014），本轮以全部业务流程跑通结束（D-015）。不再把新增性能、安全、并发或生产稳定性专项放在业务功能交付之前。

| 轮次 | 范围 | 当前验收口径 |
| --- | --- | --- |
| 1 | 需求记录、服务基础与识别边界 | 记录可恢复；提供方占位、图片检查、字典匹配和失败状态可验证 |
| 2 | 账号、MySQL、字典与媒体 | 身份和数据持久化、后台维护、数据库迁移可运行 |
| 3 | 游客识别、阅读、收藏、历史与纠错 | 原生页面与接口可贯通；模型占位和微信配置边界明确 |
| 4 | 商户、商品、POI、文化推荐与地图 | 审核关系和实际坐标驱动展示、推荐与导航请求 |
| 5 | 商户后台、优惠券与核销 | 商户管理、领取、钱包券码、核销、记录和转化统计闭环可运行 |
| 6 | 寻迹、集章、奖励与海报 | 五类节点、进度、奖励、海报选字和生成流程贯通 |
| 7 | 运营审核、配置、反馈与统计 | 工作台能够维护数据、审核内容、处理反馈和导出记录 |
| 8 | 跨端联调、使用说明与功能交付 | 修复业务断链，完成约定验证和交付记录，明确后续平台事项 |

后端、Web工作台和小程序已具备部分业务闭环。2026-09-23按原始DOCX复核后发现此前范围遗漏，尚未达到全部业务跑通；见 [原文核对](source-audit.md) 和 [验收矩阵](acceptance.md)，此处不重复维护另一套完成状态。

## 后续安排

优先补齐不依赖真实凭据的字典字段与版本、图片样本运营、文化关系与地图、埋点统计和来源归因、海报与页面差异，按核对报告的关闭条件验证。

取得外部资源后，分别接入实际模型供应商、微信账号和真实文化/商户资料，再进行真机与正式部署验证。外部依赖与业务代码缺失分别记录，不以测试夹具代替真实效果。

需要新增需求时，记录来源、影响模块和验收条件；替代旧方案时更新决策记录。当前状态保持简短，已完成过程归档到 `docs/evidence/`，避免把历史讨论当作下一轮工作目标。
